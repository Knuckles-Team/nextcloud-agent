# CONN-NEXTCLOUD-AGENT — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-NEXTCLOUD-AGENT-R001` | **File operations run through the SDK WebDAV backend.** The methods `list_files`, `read_file`, `write_file`, `create_folder`, `delete_item`, `move_item` and `copy_item` call the path methods of the SDK `WebDavBackend` (`SCION-CENTRALIZED-CAPABILITIES-R042.5`). The duplicate alias methods are gone: each operation has one method and one tool. `list_files` asks `propfind` for the Nextcloud properties `permissions`, `favorite` and `fileid`. It returns the same entry fields as before. `write_file` creates missing parent folders, and `overwrite` false keeps the conflict error. The connector deletes its own WebDAV request and listing parser code for these methods. Caller chain: the SDK per-operation tool `nextcloud_<method>` → the file method in `nextcloud_agent/api/api_client_files.py` → `WebDavBackend`. Shape: the client holds one `WebDavBackend` built from the files root URL. Depends on: `SCION-CENTRALIZED-CAPABILITIES-R042.5`. | `tests/test_files_webdav.py::test_file_methods_route_through_sdk_webdav_backend` . A mock transport receives every file request through the SDK client. A listing keeps the three Nextcloud fields. |
| `CONN-NEXTCLOUD-AGENT-R002` | **Build the WebDAV backend from the connector settings.** `get_client` in `nextcloud_agent/auth.py` reads `NEXTCLOUD_URL`, `NEXTCLOUD_USERNAME` and `NEXTCLOUD_PASSWORD` as today. The client builds `WebDavBackend` with the files root `<NEXTCLOUD_URL>/remote.php/dav/files/<username>` and the two credential values. The SDK egress guard then applies; `NEXTCLOUD_ALLOWED_PRIVATE_HOSTS` lists hosts that may resolve to private addresses. Its starting value is empty. Caller chain: `get_client` (nextcloud_agent/auth.py:11) → `NextcloudAPI` → `WebDavBackend`. Shape: one constructor change in the client base; no new setting beyond the private-host list. | `tests/test_files_webdav.py::test_backend_uses_files_root_and_private_host_setting` . The backend base URL ends with the files root. A private host refuses unless the setting lists it. |
| `CONN-NEXTCLOUD-AGENT-R003` | **Pin the SDK release with the WebDAV backend.** `pyproject.toml` pins the SDK release that carries `SCION-CENTRALIZED-CAPABILITIES-R042.5`, and `uv.lock` follows. Caller chain: the package install resolves the SDK pin. Shape: edit the dependency line and relock. | `tests/test_files_webdav.py::test_sdk_pin_carries_storage_backend` . `scion_sdk.storage.WebDavBackend` imports in the test environment. |
| `CONN-NEXTCLOUD-AGENT-R004` | **File versions, search and trash bin.** `NextcloudFiles` in `nextcloud_agent/api/api_client_files.py` lists a file's versions newest first (`PROPFIND /remote.php/dav/versions/{user}/versions/{fileid}`), restores one (`MOVE` to `restore/target`), searches by name substring with an optional MIME prefix (`SEARCH /remote.php/dav`, scope the account root or a folder), lists the trash bin and restores one item. `write_file` takes `encoding="base64"` for binary content such as photos and videos. Caller chain: tool `nextcloud_list_versions` / `nextcloud_restore_version` / `nextcloud_search_files` / `nextcloud_list_trash` / `nextcloud_restore_trash_item` → `NextcloudFiles`. Shape: one method per DAV operation. | `tests/test_business_surface.py::test_versions_search_and_trash_use_the_dav_endpoints`: versions sort newest first, restore targets `restore/target`, the search body carries the name and MIME filters. |
| `CONN-NEXTCLOUD-AGENT-R005` | **Internal shares and public links.** `NextcloudShares` in `nextcloud_agent/api/api_client_shares.py` lists shares (all, on one path, or shared with the account), reads, creates, updates and deletes one share over OCS `files_sharing`. `create_share` takes the share type by name (`user`, `group`, `public_link`, `email`, `talk`), requires `share_with` for internal types, takes password, expiry, label, note and public upload, and sends no email unless `send_mail`. Caller chain: tool `nextcloud_create_share` and siblings → `NextcloudShares.ocs_request`. Shape: one class `NextcloudShares` in `nextcloud_agent/api/api_client_shares.py`, reusing the base `ocs_request`. | `tests/test_business_surface.py::test_shares_cover_public_links_and_internal_grants`: a public link returns its URL, an internal share without `share_with` refuses, `sendMail` is false by default. |
| `CONN-NEXTCLOUD-AGENT-R006` | **Calendar events with draft invitations.** `NextcloudCalendar` in `nextcloud_agent/api/api_client_calendar.py` lists calendars with their component sets, creates and deletes a calendar (`MKCALENDAR`), lists events in a time range (`REPORT calendar-query`), reads, creates, updates (etag-guarded `If-Match`) and deletes one event. Attendees are marked `SCHEDULE-AGENT=CLIENT` unless `send_invitations` is true, so the server sends no invitation. Caller chain: tool `nextcloud_create_event` and siblings → `NextcloudCalendar`. Shape: methods on `NextcloudCalendar` in `nextcloud_agent/api/api_client_calendar.py`, built with `icalendar`, reusing the base `_dav_request` and `_dav_send`. | `tests/test_business_surface.py::test_event_invites_stay_drafts_unless_asked`: a new event is written with `If-None-Match: *`, attendees carry `SCHEDULE-AGENT=CLIENT`, and `send_invitations` removes it. |
| `CONN-NEXTCLOUD-AGENT-R007` | **Tasks (VTODO).** `NextcloudCalendar` lists open or all tasks of a task-capable calendar, creates a task with due date and priority, and updates one (summary, due, description, percent, complete or reopen) guarded by its etag. `delete_calendar_object` deletes an event or a task. Caller chain: tool `nextcloud_create_task` / `nextcloud_update_task` / `nextcloud_list_tasks` → `NextcloudCalendar`. Shape: task methods on `NextcloudCalendar` reusing its `_query` and `_put` helpers. | `tests/test_business_surface.py::test_tasks_are_vtodos_and_complete_with_etag`: completing a task writes `STATUS:COMPLETED` with `If-Match`. |
| `CONN-NEXTCLOUD-AGENT-R008` | **Contacts (vCard).** `NextcloudContacts` in `nextcloud_agent/api/api_client_contacts.py` lists address books, lists contacts with parsed name, emails, phones and organization (`REPORT addressbook-query`), reads, creates, updates (etag-guarded) and deletes one contact; deletes refuse a URL outside the account's address books. Caller chain: tool `nextcloud_create_contact` and siblings → `NextcloudContacts`. Shape: one class `NextcloudContacts` in `nextcloud_agent/api/api_client_contacts.py`, built with `vobject`, reusing `_dav_request` and `_dav_send`. | `tests/test_business_surface.py::test_contacts_round_trip_as_vcards`: the created vCard carries the fields; a delete outside the address books refuses. |
