# CONN-NEXTCLOUD-AGENT — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-NEXTCLOUD-AGENT-R001` | **File operations run through the SDK WebDAV backend.** The methods `list_contents`, `read_file`, `write_file`, `create_directory`, `delete_resource`, `move_resource` and `copy_resource` call the path methods of the SDK `WebDavBackend` (`SCION-CENTRALIZED-CAPABILITIES-R042.5`). The aliases used by the file tool keep their names. `list_contents` asks `propfind` for the Nextcloud properties `permissions`, `favorite` and `fileid`. It returns the same entry fields as before. `write_file` creates missing parent folders, and `overwrite` false keeps the conflict error. The connector deletes its own WebDAV request and listing parser code for these methods. Caller chain: MCP file tool in `nextcloud_agent/mcp_server.py` → `run_blocking(client.<action>)` → the file method in `nextcloud_agent/api/api_client_files.py` → `WebDavBackend`. Shape: the client holds one `WebDavBackend` built from the files root URL. Depends on: `SCION-CENTRALIZED-CAPABILITIES-R042.5`. | `tests/test_files_webdav.py::test_file_methods_route_through_sdk_webdav_backend` (planned in `test-spec.md`). A mock transport receives every file request through the SDK client. A listing keeps the three Nextcloud fields. |
| `CONN-NEXTCLOUD-AGENT-R002` | **Build the WebDAV backend from the connector settings.** `get_client` in `nextcloud_agent/auth.py` reads `NEXTCLOUD_URL`, `NEXTCLOUD_USERNAME` and `NEXTCLOUD_PASSWORD` as today. The client builds `WebDavBackend` with the files root `<NEXTCLOUD_URL>/remote.php/dav/files/<username>` and the two credential values. The SDK egress guard then applies; `NEXTCLOUD_ALLOWED_PRIVATE_HOSTS` lists hosts that may resolve to private addresses. Its starting value is empty. Caller chain: `get_client` (nextcloud_agent/auth.py:11) → `NextcloudAPI` → `WebDavBackend`. Shape: one constructor change in the client base; no new setting beyond the private-host list. | `tests/test_files_webdav.py::test_backend_uses_files_root_and_private_host_setting` (planned in `test-spec.md`). The backend base URL ends with the files root. A private host refuses unless the setting lists it. |
| `CONN-NEXTCLOUD-AGENT-R003` | **Pin the SDK release with the WebDAV backend.** `pyproject.toml` pins the SDK release that carries `SCION-CENTRALIZED-CAPABILITIES-R042.5`, and `uv.lock` follows. Caller chain: the package install resolves the SDK pin. Shape: edit the dependency line and relock. | `tests/test_files_webdav.py::test_sdk_pin_carries_storage_backend` (planned in `test-spec.md`). `scion_sdk.storage.WebDavBackend` imports in the test environment. |
